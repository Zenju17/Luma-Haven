# Database architecture assessment

Inspection on 2026-10-27 used the Supabase Management API against the user-confirmed Luma-Hotel project, using read-only SQL. The inspection session was `postgres`, PostgreSQL 17.11; this does not establish the role used by the deployed Django process. The repository's configured URL did not identify that project, and its direct connection failed. Do not run migrations using it until corrected and verified. `core.0001_initial` is applied. `unique_hotel_room`, `allocation_has_owner`, and the active GiST `no_active_room_overlap` constraints exist. Checks found zero quote/reservation date or occupancy violations and zero hotel percentage violations at inspection time. This is not a guarantee at migration time.

All inspected public tables were owned by postgres, with RLS disabled and no public policies. The Data API's enabled status and grants were not determined. An owner or bypass role is not protected by ordinary RLS. Treat public-schema exposure as an urgent configuration review; do not claim isolation.

Implemented: Django session authentication and global role checks, guest booking sessions, transaction-wrapped reservation/payment/check-in/check-out and some operational writes, integer minor-unit money, quote snapshots in folio entries, a unique payment event ID and attempt lock, and range exclusion. `core.0001` installs `btree_gist`. Celery expires holds; outbox records are made in payment/check-out transactions. The development payment endpoint is an emulator, not a verified provider webhook. The seed command uses get-or-create for major records but may create demo operational data.

Missing: property authorization, permission matrix enforcement by membership, reliable outbox delivery, append-only comprehensive audit, provider integration, refunds, retention workflows, property relationship constraints, and RLS. Audit covers check-in/out, cancellation, housekeeping transition and maintenance resolution only. Guests and most business records have indirect property association; staff endpoints and reports query globally and `Hotel.objects.first()` assumes one hotel. Never operate multiple properties as isolated tenants yet. Expired hold updates are not one atomic locked unit, and global event-ID replay does not validate event ownership. Finite locks, duplicate requests and concurrent payment operations require further testing.

The prepared first phase adds nullable organization ownership, membership tables, and checks; membership does not enforce access. The checks scan existing tables and can block writes; staging tests and backups are prerequisites. Large-table online alternatives should be considered. Neither the live database nor production configuration was modified. These changes are a foundation, not a completed MIS or security assignment.
